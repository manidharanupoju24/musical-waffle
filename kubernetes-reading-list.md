## Kubernetes

| Done | Resource | Notes |
|:---:|---|---|
| ⬜ | [QoS classes](https://kubernetes.io/docs/concepts/workloads/pods/pod-qos/) in Kubernetes | Guaranteed / Burstable / BestEffort, derived from requests and limits. Drives eviction order and OOM-kill priority. |
| ✅ | [Ownership of objects/subresources](https://kubernetes.io/docs/concepts/overview/working-with-objects/owners-dependents/) in Kubernetes | Only one owner can have `controller: true`. Namespaced dependents can't have owners in other namespaces. |
| ⬜ | [Status subresource](https://kubernetes.io/docs/tasks/extend-kubernetes/custom-resources/custom-resource-definitions/#status-subresource) | `/status` updates only status, and the main endpoint ignores status changes. `generation` bumps only on spec changes, so pair it with `observedGeneration`. |
| ⬜ | How do we add/remove ownerRefs for a Kubernetes resource? — [controllerutil](https://pkg.go.dev/sigs.k8s.io/controller-runtime/pkg/controller/controllerutil) | `SetControllerReference` for the managing owner (what `Owns()` relies on), `SetOwnerReference` for extra owners, `RemoveOwnerReference` to detach. |
| ⬜ | How does a finalizer work on a single controller in an operator? — [Finalizers](https://kubernetes.io/docs/concepts/overview/working-with-objects/finalizers/), [Kubebuilder: using finalizers](https://book.kubebuilder.io/reference/using-finalizers) | Add the finalizer early. When `deletionTimestamp` is set, run cleanup and then remove it. The object stays until the finalizer list is empty. |
| ✅  | Kubernetes [Garbage collection](https://kubernetes.io/docs/concepts/architecture/garbage-collection/) | Background (default), foreground (`blockOwnerDeletion` matters here), and orphan propagation policies. |
| ⬜ | What is a watcher in a controller and how does watching a resource happen within the controller? — [API watch semantics](https://kubernetes.io/docs/reference/using-api/api-concepts/#efficient-detection-of-changes), [Kubebuilder: watching resources](https://book.kubebuilder.io/reference/watching-resources) | List, then watch from a resourceVersion. A 410 Gone forces a relist. `For` / `Owns` / `Watches` map events to reconcile requests. |
| ⬜ | Informers, listers & workqueue — [client-go controller internals](https://github.com/kubernetes/sample-controller/blob/master/docs/controller-client-go.md), [cache](https://pkg.go.dev/k8s.io/client-go/tools/cache), [workqueue](https://pkg.go.dev/k8s.io/client-go/util/workqueue) | Reads come from a shared cache, so they can be stale. The workqueue dedupes keys and handles rate-limited requeues. |
| ⬜ | resourceVersion & optimistic concurrency — [Resource versions](https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions), [API conventions: concurrency control](https://github.com/kubernetes/community/blob/master/contributors/devel/sig-architecture/api-conventions.md#concurrency-control-and-consistency) | Updating with a stale resourceVersion returns 409 Conflict. Handle it with a requeue, `RetryOnConflict`, or a Patch. |
| ⬜ | Level-triggered reconciliation — [Controllers](https://kubernetes.io/docs/concepts/architecture/controller/), [Kubebuilder: controller overview](https://book.kubebuilder.io/cronjob-tutorial/controller-overview) | Reconcile acts on current state, not on the event (a request is just namespace/name). It must be idempotent. |
| ⬜ | How does a Service track its backend pods at scale? — [Endpoint slices](https://kubernetes.io/docs/concepts/services-networking/endpoint-slices/) | Scalable replacement for Endpoints: a Service's backends are split across slices (100 endpoints each by default), linked via the `kubernetes.io/service-name` label. Endpoints carry `ready` / `serving` / `terminating` conditions. |
